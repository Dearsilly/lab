# AES 系统答辩演示脚本

## 演示准备

**Android（主要演示设备）**：
- 安装 APK 到手机，确保模型文件在 `assets/` 中
- 手机连接投影/投屏
- 准备测试文本（中英文各一篇）

**Web（辅助对比）**：
```bash
# 终端 1：启动 API
python api/app.py

# 终端 2：启动 UI
streamlit run ui/app.py
```

---

## 演示流程（约 10 分钟）

### 场景 1：开场 — 问题引入（30 秒）

**讲解词**：
> 作文评分是教师最耗时的工作之一。一个老师带 4 个班，每次作文要批 200 篇。我们的系统用深度学习自动完成这项任务——输入一篇作文，BERT 模型在几百毫秒内给出总评分、三维度分项分和文字评语。系统有两个版本：Android 本地推理版和 Web 服务版。

---

### 场景 2：Android 单篇评分 — 中文作文（2 分钟）

**操作**：
1. 打开手机上的 AES 评分 App
2. 底部 Tab 默认在「评分」页
3. 语言选择保持「自动」
4. 粘贴一篇中文作文（可现场写或从 `samples/high_score_zh.txt` 复制）
5. 点击「提交评分」

**展示要点**：
- 语言自动检测为中文
- 总分仪表盘（大号数字 + 渐变进度条）
- 三维度卡片：内容(绿)、结构(靛)、语言(橙)
- 雷达图可视化三个维度的均衡性
- 中文模板评语（总分评语 + 三个维度分别评语）
- 底部显示推理耗时

**讲解词**：
> Android 版的核心亮点是模型在手机本地运行，不需要网络、不需要服务器。我们用的是 PyTorch Mobile，把训练好的 BERT 模型直接打包进 APK。分词器也是用 Kotlin 从零实现的 WordPiece 算法——读取 vocab.txt 构建词表，对中文做字符级切分，对英文做子词匹配。推理结果除了总分，还有启发式拆分的三维度分数和模板化中文评语。雷达图是用 Compose Canvas 自绘的，没有引入第三方图表库。

---

### 场景 3：Android 英文评分 + 语言自动检测（1.5 分钟）

**操作**：
1. 切换到英文文本（`samples/high_score_en.txt`）
2. 语言选择保持「自动」，再次提交
3. 观察自动识别为英文，评分和反馈正常

**展示要点**：
- 自动检测为英文
- 英文模型评分结果
- 同一个 App、同一套代码处理两种语言

**讲解词**：
> 语言检测用的是简单的字符规则——统计中文字符占比，超过 50% 走中文模型，否则走英文模型。不需要额外的 NLP 库，零依赖。两个 BERT 模型加起来约 800MB，在手机 CPU 上推理速度约为 1-5 秒，完全可接受。

---

### 场景 4：Android 中英对比 + 批量评分（2 分钟）

**操作（对比）**：
1. 切换到「对比」Tab
2. 输入一篇中英文混合的文本
3. 点击「开始对比」
4. 展示左右两列：英文模型 vs 中文模型评分结果

**操作（批量）**：
1. 切换到「批量」Tab
2. 选择预先准备的 CSV 文件（`samples/batch_demo.csv`）
3. 点击「开始批量评分」
4. 观察进度条和逐条结果列表

**讲解词**：
> 对比功能同时对同一篇文本调用中英文两个模型，直观展示两个模型对相同内容的理解差异。批量评分支持 CSV 导入，逐条推理并展示进度和结果列表。这两个功能在 Web 版也有对应实现，底层用的是同一套 Flask API。

---

### 场景 5：模型架构与训练流程（2 分钟）

**操作**：
1. 切换到「设置」Tab，展示模型加载状态和 QWK 信息
2. 切到白板/PPT 展示架构图

**讲解词**：
> 系统架构分为三层：数据层、模型层、应用层。数据层使用 ASAP 英文作文数据集（12,979 篇）和其 Google 翻译中文版（3,950 篇）。模型层基于 BERT-base-uncased 和 BERT-base-chinese，在 [CLS] token 上加一个 Dropout + Linear + Sigmoid 回归头，输出 [0,1] 区间的分数。损失函数是 MSE，优化器 AdamW with warmup。训练时我们采用了严格的 prompt 隔离策略——按 essay_set 级别划分训练/测试集，同一题目的作文不会同时出现在两边，防止数据泄露。这导致英文模型 QWK 约 0.58，看起来不高，但这是更真实的跨题目泛化能力。中文模型 QWK 达到 0.79。
>
> 应用层我们做了两个版本：Android 版用 PyTorch Mobile 做本地推理，Kotlin + Jetpack Compose 写 UI；Web 版用 Flask 做 API、Streamlit 做前端。两个版本共享同一套训练好的模型权重。

---

### 场景 6：Web 版快速展示（1 分钟）

**操作**：
1. 展示浏览器中 Streamlit 界面
2. 单篇评分（仪表盘 + 雷达图 + 反馈卡片）
3. 中英界面切换
4. 批量评分上传展示

**讲解词**：
> Web 版的功能和 Android 版一一对应。区别在于推理在 Flask 服务器端的 GPU 上完成，前端通过 REST API 调用。Streamlit 的纯 Python 开发模式让我们快速完成了从模型到 UI 的完整闭环。

---

### 场景 7：工程总结（1 分钟）

**讲解词**：
> 总结一下，我们实现了：
> 1. 中英文双模型 BERT 作文评分，Android 本地推理 + Web 服务双版本
> 2. 多维度评分输出 + 雷达图可视化 + 模板化评语反馈
> 3. 完整的批量评分流水线
> 4. 17 项单元测试 + 41 项 E2E 测试覆盖
> 5. Kotlin 实现了完整的 BERT WordPiece 分词器
>
> 后续改进方向：收集中文作文数据替代翻译数据、部署多任务模型替代启发式维度拆分、引入 Longformer 支持超长文本。

## 常见答辩问题准备

### Q1: QWK 为什么偏低？
> 我们采用了 prompt 隔离评估——训练集和测试集包含完全不同的作文题目。这比同题目内随机划分更严格，QWK 约 0.55-0.60，但更能反映模型对新题目的泛化能力。这在 AES 文献中是标准做法。中文模型 QWK 0.79 是用随机划分得到的，偏高，因为翻译数据同源。

### Q2: 中文模型训练数据从哪来？
> 将 ASAP 英文作文通过 Google Translate 翻译为中文，保留原始评分标签。局限是存在翻译腔，对自然中文表达的适应性有限。已在文档中说明，并计划收集真实数据改进。

### Q3: 维度评分怎么实现的？
> 当前版本采用启发式拆分——从总评分按系数（×0.95 / ×1.02 / ×1.03）拆分为内容、结构、语言。架构上已预留了多任务模型（AESMultiTaskModel，4 个独立回归头），只需维度标注数据即可训练。当前方案是标注数据缺失下的务实折中。

### Q4: Android 版的 BERT 分词器是自己写的吗？
> 是的。Kotlin 实现 WordPiece 算法：读取 vocab.txt 构建 HashMap，basicTokenize 处理中英文字符切分，wordPieceTokenize 做贪心最长子词匹配（## 前缀标记）。约 100 行代码，零外部 NLP 依赖。

### Q5: Android 版为什么不调用服务器而是本地推理？
> 本地推理让 App 离线可用，不依赖网络和 GPU 服务器。对于演示场景，不需要观众连接同一个 WiFi 或配置服务器地址。PyTorch Mobile 让模型直接跑在手机 CPU 上，虽然比 GPU 慢，但 1-5 秒的推理延迟对用户体验是可接受的。

### Q6: 为什么不引入数据库/用户认证？
> 工程实践项目刻意控制了复杂度边界。核心价值在模型训练和评分推理流水线，而非通用 Web 基础设施。当前系统已能完整演示核心功能。
